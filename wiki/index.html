01 / 项目概览

项目用途与核心概念

REA（Reverse Engineer Anything）是一套本地逆向分析工具，将应用包、原生二进制、网页和运行时行为的分析能力统一到 CLI 与 MCP。 npm 包名为 rea-agents，安装后同时提供 rea 和 rea-agents 命令。AI Agent 通过 MCP 调用这些能力，也可以由开发者直接在终端执行。

例如，你想理解一个 Electron 应用如何实现搜索、剪贴板或插件加载。REA 可以读取应用包，建立模块及依赖关系，定位 preload、IPC 与原生扩展，必要时补充运行时观察；Agent 再用这些证据解释实现方式，或在你的项目中编写并验证类似功能。

01 / QUESTION明确问题选择目标文件、应用、网页和待研究功能。
02 / INSPECT执行分析CLI 或 Agent 调用静态解析器及配置的分析引擎。
03 / EVIDENCE保留证据返回目标身份、原始事实、归一化结果与未知项。
04 / VERIFY解释与重建追踪关键路径，写出实现，再用原目标或测试验证。

适用场景

  • 功能理解与实现参考：追踪搜索、导出、菜单动作、IPC、原生 API 调用等路径。
  • 包和依赖审查：检查 ASAR、ZIP、应用目录、.NET 程序集、APK 的结构与依赖边界。
  • 版本差异分析：对比两个构建产物、函数、模块关系或运行场景的证据。
  • 研究与复现：对二进制反汇编或伪代码进行解释，结合输入输出样例验证重建结果。
  • 行为观察：按明确目标记录网页网络、浏览器交互、进程终端与文件系统变化。

输出究竟是什么

原生分析可返回汇编、伪代码、字符串、符号、调用与引用；JavaScript/Electron 返回模块及其关系；.NET 返回元数据、CIL 与声明的原生依赖。REA 将这些结果包装为 Evidence：带有来源、目标身份和不确定性信息的分析记录。

REA 自身提供工具和工作流。自然语言解释、自动编写重建代码通常由接入的 Agent 完成。反编译伪代码和静态关联可提供线索，但不会自动证明恢复了原始源码，或者覆盖了所有运行时路径。

CLI、MCP、Skill 与 Provider

名称 作用 如何使用
CLI 终端命令、脚本、JSON 文件输出 rea COMMAND ...
MCP Server 将工具、提示和会话暴露给 Agent rea mcp，通常由客户端启动
Skill 教 Agent 怎样选择目标、分步调查、记录证据 rea setup 同时安装匹配版本的工作流说明
Provider 实际执行某一类分析的适配器 如 Hopper、Ghidra、IDA、浏览器或静态解析器
Evidence 可追溯的分析记录 显示结果、保存 JSON、导出 bundle、进行比较
Snapshot 复用符合条件的已成功分析结果 原生 CLI 使用 --snapshot；MCP 使用会话保存参数

数据在哪里处理

REA 的目标分析在本地进行。接入 Agent 后，工具结果会交给 Agent；模型提供方的数据处理规则仍取决于该客户端。静态读取与运行时操作的影响也不同：静态 JS/.NET 检查不执行目标程序，主动观察则可能启动目标、点击页面或写入场景指定的文件。

Windows 与 WSL 如何选择

本机 Windows 的 Ghidra 支持属于实验 P0，主要为固定本地 NTFS 卷上的 x86/x86-64 PE，保持只读；不能据此宣称已完整覆盖 Unix 引擎、GUI 控制或所有原生格式。需要 Linux 专用工具时，使用 WSL 中的 Linux REA，并在同一环境配置对应依赖。

Windows REA 使用 D:/apps/example 或 C:/tools/... 路径；WSL REA 使用 /mnt/d/apps/example 或 /absolute/path/...。两边的 Node、JDK、Ghidra 与 Agent 环境配置应各自匹配。网页 Wiki 的本地服务运行于 WSL，浏览器访问本机 127.0.0.1。

04 / 安装与配置

安装选择与版本边界

REA 的 npm 包名是 rea-agents，安装后提供 rea 和 rea-agents 两个命令，二者均指向 scripts/rea.mjs。当前源码的 package.json 版本为 6.4.0，许可证 MIT。

运行时支持 Node.js 22.x（≥22.19）、24.x（≥24.11）或 26+。Node.js 23、25 与预发布版本不受支持。仓库开发环境另行固定为 .nvmrc 中的 24.18.0、packageManager 中的 npm 11.16.0；开发工具链与已安装包支持范围应分别理解。

docs/installation.md 记录：2026-10-11 核查的 npm 最新版为 6.4.0，对应发布提交 a56f7bb668ab23fec8d33f7af353ac7ed2fe1895。本次分析提交更晚，所以同样的版本字符串不能证明开发源码与 npm 发布包具有完全相同的功能与字节。本 Wiki 按固定源码说明能力；使用 npm 时以服务器实际公布的工具与输入 schema 为准。

核查发布版本：

bash
npm view rea-agents dist-tags.latest

A. 一次性 CLI 使用

不要求全局安装，适合先尝试静态 JavaScript/Electron 分析：

bash
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

app 可以是提取后的应用目录或 .asar 文件。这类静态分析不需要 Hopper/Ghidra/IDA。

B. 全局 CLI 使用

bash
npm install --global rea-agents
rea --help
rea providers --json

npm install rea-agents 不带 --global 只安装到当前项目的 node_modules/.bin，不会自动让 shell 全局识别 rea。

C. 给 AI 客户端配置 REA

bash
npx rea-agents@latest setup

向导选择客户端、显示准确的改动路径、备份现有配置、经操作者确认后写入 MCP 配置和匹配的工作流 skill。完成后重启相应 AI 客户端。npm 下载包的许可不等于 REA 向导内的配置修改或 Hopper 安装许可。

Bun 对应入口为 bunx rea-agents@latest setup。项目 CI 验证 Node.js；Bun 的兼容性与内存控制有独立边界，不能把 Bun 视为 Node 的同等实测基线。

06 / 安装与配置

原生分析引擎配置

REA 是编排和证据层，深度原生分析需要外部 provider。静态 JS/.NET 分析不需要原生 provider。

Ghidra

支持已有的 Ghidra 12.1.x，文档实测基线是 12.1.4 + 64 位完整 JDK 21。Ghidra 安装自身的 application.java.min/max 决定 JDK 范围；当前 12.1 要求 JDK 21+。完整 JDK 必须具有 javac，并具有对应主机架构的原生 decompiler。

Linux/macOS：

bash
export GHIDRA_INSTALL_DIR=/absolute/path/to/ghidra_12.1.4_PUBLIC
export JAVA_HOME=/absolute/path/to/jdk-21
rea doctor --provider ghidra --json
rea analyze /absolute/path/to/program --provider ghidra --json

Windows PowerShell：

powershell
$env:GHIDRA_INSTALL_DIR = "C:\tools\ghidra_12.1.4_PUBLIC"
$env:JAVA_HOME = "C:\Program Files\Java\jdk-21"
rea doctor --provider ghidra --json
rea providers --json

主机支持 Linux x64/arm64、macOS x64/arm64；Windows x64 是实验性 P0，限定固定本地 NTFS 上的 x86/x64 PE 应用与 DLL，仍为只读。Linux ARM64 的官方归档可能不含 linux_arm_64 decompiler，需要操作者另行构建。REA 不安装 Ghidra/Java，不修改 Gatekeeper quarantine。

会话使用临时 Ghidra 项目与隔离的 home/cache/config/temp，不打开用户已有项目。open_binary 绑定并验证目标，实际 import/auto-analysis 在首个需要引擎的查询上延迟启动。默认启动超时 330000 ms，大型文件可设置：

bash
export REA_GHIDRA_STARTUP_TIMEOUT_MS=900000

该值必须为 1–2147483647 的十进制整数；它与客户端单次 MCP 工具调用超时、MCP 进程启动超时是三个不同的期限。

Hopper

Hopper 是独立的商业软件，可使用厂商 demo 或已有许可。macOS 12+ 与官方列出的 Linux 基线（Ubuntu 24.04+、Fedora 41+、Nobara 44+、64 位 Arch/CachyOS/Omarchy）有向导支持。Windows 不支持 Hopper 安装。

macOS 经确认的向导安装到 ~/Applications/Hopper Disassembler.app，不使用 Homebrew 或管理员权限；Linux 经确认会安装相应包及 Xvfb/Python/X11/XTEST 依赖。REA 原生启动需要时才启动 Hopper。

bash
export HOPPER_LAUNCHER_PATH=/absolute/path/to/Hopper
rea doctor --provider hopper --json
rea analyze /absolute/path/to/program --provider hopper --json

默认 macOS 启动路径为 /Applications/Hopper Disassembler.app/Contents/MacOS/hopper。Linux 优先 /opt/hopper/bin/Hopper，其次 ~/.local/share/rea/hopper/bin/Hopper。默认启动 deadline 120000 ms，通过 REA_HOPPER_STARTUP_TIMEOUT_MS 扩大，整数范围与 Ghidra 相同。

首次 macOS 启动可能需要选择 demo/激活已有许可；Automation/Apple Events 拒绝时到系统“隐私与安全 → 自动化”授予启动 REA 的应用相应许可。Linux 使用私有 Xvfb 显示，合作 REA 进程每个用户只能保留一个 Linux Hopper 应用所有权；冲突时需关闭所属 REA 会话后再切换。GUI 焦点切换并不改变已绑定目标。

IDA

REA 连接操作者已有的 mrexodia/ida-pro-mcp，不安装/激活/授权 IDA、Hex-Rays 或 Python。支持“已打开 GUI 的 legacy 1.4.0 工具”与“headless database supervisor API”两种 profile，功能边界不同。

bash
export REA_IDA_MCP_CONFIG=/absolute/path/to/ida-mcp.json
export REA_ANALYSIS_PROVIDER=ida
rea function /absolute/path/to/original-program main --json
rea decompile /absolute/path/to/original-program main --json

Evidence、缓存、返回值如何读

Evidence schema 核心字段：

字段 解读
evidence_id ev_ + canonical semantic SHA-256，校验 payload 是否变动；不是作者签名或结论真实性认证
subject target digest/format/architecture/local_path；可能为 null，不能编造 target identity
provider / analysis_profile producer 与分析条件；profile 必须存在，可为 null；有对象时 provider 要一致
operation / parameters 真正做过的操作与输入
raw_result 原始 producer representation；没有则 null
normalized_result 具体操作结果，读取 graph/inspection/coverage 等从这里开始
confidence observed / derived / inferred
authority shipped-artifact / controlled-replay / historical-reference / external-service / analyst-inference
limitations / locations / evidence_links 不能证明的内容、artifact-path/address/file-offset 位置、关联 Evidence

semantic ID 包含 raw+normalized result、profile、authority 等；subject display name/local_path 不在语义投影中，但 digest/format/architecture 在。Evidence IDs 能发现篡改，不能证明第三方真实执行过 claimed observation。

CLI 默认 TOON，给 JSON consumer 保存必须 --json；terminal 时 indented，pipe/redirect compact。stderr 有 rea_progress，stdout 最终文档。0 仅表示 operation completed，结果仍可 partial/warnings/unknown；1 失败；signal 常见 128+N。处理管道可 set -o pipefail，避免 jq 覆盖 REA exit status。

bash

本机访问与重新启动

默认地址为 http://127.0.0.1:8765/。服务只绑定本机，提供 wiki 目录内容；源码目录及 .git 不在此服务根目录中。

在 WSL/Linux 中运行：

bash
cd /mnt/d/projects/rea
python3 wiki/serve.py --port 8765

也可以执行 sh wiki/start-wiki.sh。在当前 Windows 机器中可双击 wiki\start-wiki.bat，它调用已有 WSL 的 Python。若使用原生 Windows Python，可在 PowerShell 中运行：

powershell

py -3 .\wiki\serve.py --port 8765

终端打印地址后即可访问。按 Ctrl+C 停止；如端口被占用，改用 --port 8766，并访问对应端口。Windows 访问 WSL 地址依赖本机 localhost 转发；若环境关闭了该机制，可直接在 Windows Python 中启动服务。挂载不代表已配置开机自启；服务结束后使用以上命令重新启动。

备份、修改与重新生成

直接备份 wiki 目录即可；index.html 是自包含文件，可单独分享或离线打开。分析底稿为 Markdown，修改后通过 build.mjs 重新生成；生成器需要 Node.js 及 marked，可用 --renderer 指定已有 marked.esm.js 的绝对路径。它不会构建或修改 REA 运行时。

bash

node wiki/build.mjs --renderer /absolute/path/to/marked/lib/marked.esm.js

常见问题

我只想看 Electron / ASAR，需要安装 Ghidra 吗？

静态 JavaScript/Electron 分析无需原生引擎。先执行 rea analyze-javascript-application PATH --json。当问题涉及 .node 等原生模块的内部实现时，再配置支持该文件格式的 Provider。

只安装 Skill，Agent 就能调用 REA 吗？

Skill 是工作流说明；实际调用还需要 MCP Server 注册。通常用 npx rea-agents@latest setup 同时完成，再重启 Agent 并确认工具列表。

REA 是否直接把闭源程序变成完整源码？

REA 提供伪代码、汇编、模块、元数据和行为证据。完整重建由调用者或 Agent 根据证据实施，还需功能测试或原目标对照。命名缺失、优化、动态加载、外部服务和未观察路径都可能保留为未知项。

Ghidra 首次调用很慢，open 成功为什么还在等待？

open_binary 主要建立目标与 Provider 绑定。Ghidra 导入和自动分析由第一次实际查询延迟触发，服务端启动截止时间与客户端工具调用截止时间不同。先看 session 的 analysis_activity，按安装及排错章节处理。

退出码 0 是否代表分析完备或重建等价？

仅表示操作完成；结果仍可能部分覆盖、带警告或包含未知项。应结合 Evidence 的来源、覆盖范围、置信度及具体验证记录判断。

能把一次 MCP 返回的 evidence_id 用到另一终端命令吗？

单个 retained Evidence ID 属于当前 MCP 连接，不能作为另一进程的持久数据库索引。跨 CLI 命令使用完整保存的 Evidence JSON，跨连接则导出 bundle 或符合条件的 snapshot。

全量 doctor 不健康，是否说明所有功能都无法使用？

默认 doctor 是全面审计，未配置的可选引擎也会出现在报告里。对自己的工作流执行限定检查，例如 rea doctor --provider ghidra --json 或 rea doctor --client codex --json；静态 JS 可直接尝试相应命令。

Wiki 的本地 HTTP 服务就是 REA MCP Server 吗？

两者独立。这里的 Python 服务只展示静态文档，默认端口 8765。REA MCP 的默认传输是 stdio，由 Agent 启动并调用，不通过这个 Wiki 服务执行分析。

需要填写模型 API Key 或启动数据库吗？

直接 CLI 静态分析不需要模型账号或数据库；Agent 自身的模型配置由客户端管理。某些分析 Provider 需要已有软件、许可或本地 endpoint。当前 Wiki 没有账号、数据库或外部服务依赖。
